# Assigment 12: Generate Count Matrixes


## How to use these Makefiles: 

Use the Makefile in the main directory. If you wish to examine the underlying R scripts, examine the src folders in the gene and transcript files, respectively. 

To download the necessary data, run 

``` 
make download
```

```

├── gene_count_matrix.csv
├── transcript

├── transcript_count_all.csv
├── transcript_count_matrix.csv
├── transcript_count_matrix_shorter.csv
└── transcript_count_matrix_tximport.csv
```
To run the a gene-level analysis on the RNA-seq data, use 

```
make gene
```
Conversely, for transcript level analysis, use 

```
make transcript
```

or
  
``` 
make transcript_shorter
```

These should yield the same results, but it may be fun to try run them both. 

Finally, the gene and transcript counts can be compared by running

```
make count_transcripts
```
and 

```
make compare
```

This will yield a csv with 6 additional column that shows ***gene-matrix minus transcript-matrix counts*** for each sample.

I then prompted the AI to add in the correct gene names using the package biomaRt. 

```
In the exsisting R_script, create a new column called "gene name" that converts the Ensembl gene names into common gene name. Use biomaRt to convert these names
```

This initally generated multiple problems. I got the error 
```
Ensembl site unresponsive, trying useast mirror
Ensembl site unresponsive, trying asia mirror
Error in .chooseEnsemblMirror(mirror = mirror, http_config = http_config) :
  Unable to query any Ensembl site
Calls: <Anonymous> -> .chooseEnsemblMirror
Execution halted
(stats)
```

The in-house Visual Studio AI assistant recommended using mirror = "useast" or "asia". It claimed ***The SSL handshake error means R couldn’t establish a secure connection to Ensembl; if all mirrors fail, check your internet connection, VPN/proxy, firewall, and whether R and biomaRt are up to date.***

However, it seemed like the error messages suggested the useast and asia mirrors had already been tried, so I was skeptical. I found that googling the error message yielded much better results: apparently,  Ensembl discontinued BioMart on its main site and retired its regional mirrors (useast and asia) during a mid-2026 platform transition. I found a reddit post saying using "host = "https://e116.ensembl.org" is a workaround that will use an older version of the platform. The same Reddit post was full of distraught people, though, so it seems this isn't a permanent workaround, and that the biomaRt tool may not be viable long-term. A potential alternative could be the R package annotables. 

So, in this case, I found going past the AI agent to be a more informative and up-to-date option than trying to let itself figure itself out. 


I also noticed that the Rscript the AI generated is decently long. Something I've noticed in the AI-generated scripts is that it automatically codes for a lot of error messages (e.g. if (anyDuplicated(GENE_ANNOTATIONS$ensembl_gene_id)) { stop("biomaRt returned multiple gene names for an Ensembl gene ID.")). This may be helpful when these situations do arise, but I find that they tend to bloat out the code and make it harder for me to intuitively understand what it's doing.

I also found that the AI ignored my instructions to annotate heavily and I had to ask it to add in annotations for the code. I put in my instructions in the customization tab to be user specific across projects and workspaces, so I'm not quite sure why it's ignoring them.
